# Production BOM and Truth-Layer Release Design

Date: 2026-10-13
Status: approved via plan review
Supersedes: docs/superpowers/specs/2026-10-13-blog-artifact-generators-design.md

**Decisions made with the user (2026-10-13):** truth layer blocks, quality advisory except the three scores; facts come from a research packet inside the production BOM; BOM items marked must/should, must blocks; `/research` adds a page-1 coverage map and a keyword shortlist; old stack retired after cut-over; CI stays connector-free.

1. **Production BOM** `research/production-bom-<slug>-<date>.json`, schema `simpro-production-bom/v1`. Contents: identity (slug, date, run_id, brand, market, workflow_mode, article_path), keyword (primary, secondary, shortlist with Semrush numbers and the decision rule, bound to the saved Semrush decision artifact), serp (query, top-10 results with H2/H3 outlines, coverage topics with counts), sections (heading, purpose, priority), facts (id, claim, url, quote, verified_at, priority), proof (id, claim_id, kind, approved text, customer, url, priority), paa (artifact binding, questions with priority), links (url, anchor, kind, priority), cta, schema_notes, context (pack/receipt binding or not_applicable reason). Every bound artifact carries path and sha256.
2. **Honest by construction.** Claude writes a BOM spec (judgment). `production.bom build` admits a fact only if its quote is found on the live page at build time, and a proof item only if its claim_id is an approved claim in the validated context receipt; its text is copied from the claim, never typed. Nonconnector brands take proof only from approved rows in `config/nonvault-customer-proof-index.json`.
3. **Page-1 coverage map.** `production.serp_coverage` fetches the top-10 URLs from existing SERP evidence concurrently, extracts H2/H3, normalizes headings, counts how many pages cover each topic. Topics covered by at least half of the fetched pages are suggested must sections; topics covered by two or more are suggested should; PAA questions no page covers are suggested should (differentiation). Claude confirms or overrides in the BOM spec.
4. **Release check** `python -m data_sources.modules.production.release <article>`. Runs these groups concurrently and writes `research/releases/<slug>-<date>-<run8>-<n>/release-record.json` (schema `simpro-release-record/v1`):
   - Truth (blocking): links resolve; every `inline_required` or `section_source_allowed` claim from `analyze_proof_links` cites a BOM fact URL; that fact's quote is still on the page (unreachable is a warning that falls back to the build-time verification; reachable-without-quote or 404/410 blocks); numbers in the claim appear in the fact's quote; customer and review quotes match a BOM proof item verbatim; every FAQ question is a BOM PAA question; no `editorial_process_leakage`.
   - Coverage: every must item present (section headings, commercial pillar link with its anchor, must facts and proof used, must PAA questions in the FAQ, primary keyword in title, H1, and first 100 words) blocks; should items are reported.
   - Scores (blocking): content 85, SEO floor 90, AEO/GEO 90, computed by the existing scorers fed a proof view rendered from the BOM.
   - Advisory: other lint findings, scorer priority fixes, should-coverage gaps.
   - Exit 0 pass, 1 blocked, 2 operational or argument error. The record holds article sha256, BOM sha256, every check result, scores, and passed.
5. **Concurrency.** Network work uses `PublicHttpTransport.request_many` (bounded workers, per-host limits, shared cache). The truth, coverage, and lint groups run in a `ThreadPoolExecutor`; the three scorers run in a `ProcessPoolExecutor`. Both pools size from `SEOMACHINE_RELEASE_WORKERS` (default 2, because this machine hits low-memory kills); `1` runs sequentially.
6. **Subagents (command docs).** `/research` dispatches parallel lanes: vault context and approved proof, page-1 coverage, PAA capture, source facts. Semrush stays one lane (one Chrome session). `/write` uses one writer for voice, then parallel advisory reviewers (editor, SEO, AEO, fact-check) whose findings the writer applies. Subagents never write public copy and never add a BOM entry that the builder has not verified.
7. **Publishers.** WordPress and Grav publish only when the latest release record passed and its article sha256 equals the file being published; they no longer re-run the old readiness stack.
8. **Retirement.** After cut-over, delete every module not reachable from the keep-list entrypoints (production package, scorers, research scripts, selectors, context_build, publishers, CLIs still referenced by commands) and their tests. Past releases remain as files; git keeps history.

**Out of scope:** Semrush/Chrome capture recorder internals (5A) beyond the transcript-number check in Task 4; Hindsight evidence generation (Hindsight stays an optional private research input that never enters the BOM's public items).
