# Agent Governance Rule

Use this rule when changing agent, rule, skill, command, MCP, or steering documentation in this proof-sensitive repo.

- Superpowers owns process mechanics: planning, execution, TDD, review, verification, worktree setup, and completion handoff.
- This repo rule owns local governance: proof sensitivity, scope control, evidence status, and mirror discipline.
- Do not copy Superpowers checklists, sub-skill triggers, execution workflows, or plugin lifecycle language into repo rules; do not duplicate process rules that already live in the Superpowers plugin.
- Before changing any agent, rule, skill, command, MCP, or steering doc, inspect sibling surfaces and mirror required repo-specific behavior across Cursor, Agents, and Claude when those surfaces already carry the same contract.
- Never synthesize proof-sensitive data, customer claims, review claims, metrics, rankings, PAA questions, quotes, or source support.
- Treat verified evidence as different from attempted work, dry-run output, inferred fit, stale memory, and blocked access. Report each status plainly.
- Do not mark work ready, fixed, passing, or complete unless the relevant gate, test, readback, or source check has been run in the current work.
- Keep edits narrowly scoped to the user's request. Do not rewrite unrelated docs, refactor command contracts, or alter top-level steering files as cleanup.
- Do not edit `AGENTS.md` or `CLAUDE.md` unless the user explicitly asks for those files to change.
